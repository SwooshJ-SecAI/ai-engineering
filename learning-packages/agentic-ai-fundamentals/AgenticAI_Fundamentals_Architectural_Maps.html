CH 5 · APPLICATION

1 · The Agent Loop (Perceive → Think → Act → Observe)

The execution engine of every agent. Each observation feeds the next round of reasoning; the cycle repeats until the objective is met or a stopping condition fires.
Why it works: Solving iteratively rather than one-shot lets the agent revise as new information arrives — each observation changes reasoning, which changes the next action. ReAct forces explicit reasoning before acting, improving reliability and making the trace auditable.
Fails when: There is no stopping condition — the agent loops forever on an unsolvable task, or burns budget in an infinite retry loop.
CH 8–10 · APPLICATION

2 · The RAG Pipeline

Retrieval-Augmented Generation decouples knowledge from the model. Documents are chunked, embedded, and stored once; at query time the question is embedded, similar chunks are retrieved, and the LLM answers from that grounded evidence.
Why it works: Updating a knowledge base is far cheaper than retraining a model, and grounding the answer in retrieved evidence reduces hallucination. Embeddings make it possible to match meaning, not keywords.
Fails when: Indexing and querying use different embedding models (incompatible coordinate systems), or poisoned/wrong chunks are retrieved — the model faithfully grounds on bad evidence.
CH 7 · APPLICATION

3 · Memory: Context vs. the Four Types

Context lives in the model's window and is erased between sessions; memory persists outside the model and is retrieved when needed. Episodic and semantic memory live in external stores.
Why it works: Separating reasoning (the LLM) from storage (external DBs) from retrieval keeps systems scalable, modular, and auditable — and lets agents personalize across sessions.
Fails when: 'The agent should remember X' is misread as fine-tuning the model instead of storing X externally — producing expensive, brittle designs.
CH 12 · ANALYSIS

4 · Choosing a Reasoning Architecture

The LLM supplies intelligence; the reasoning architecture organizes it. Different problems demand different thinking styles — route the problem to the pattern that fits.
Why it works: Reasoning quality is separate from raw model intelligence and often more decisive. ReAct suits changing environments (it can act mid-reasoning); ToT explores branches before committing; Reflection self-critiques.
Fails when: The pattern is over-engineered for the task — e.g. Tree-of-Thoughts branching wasted on simple arithmetic where Chain-of-Thought suffices.
CH 13 · ANALYSIS

5 · Multi-Agent System (Orchestrator–Worker)

A team of specialized agents coordinated by a supervisor that decomposes work, assigns specialists, and combines results. Shared memory keeps every agent reasoning from consistent information.
Why it works: Distributing work by expertise scales better than one generalist as objectives grow; specialists outperform a generalist, and parallel execution cuts latency. Consensus across agents improves reliability.
Fails when: Agents proliferate without measurable value — coordination overhead, cost, conflicts, and latency outweigh the benefit. Earn the complexity: start with one agent.
CH 19 · ANALYSIS

6 · The Enterprise AI Stack

Enterprise AI is layered infrastructure, not a single app. Each layer depends on the one below; standardization and reusability across layers prevent AI silos.
Why it works: Shared services (identity, retrieval, guardrails, observability) built once and reused across the stack reduce cost, risk, and inconsistency as the number of agents grows into the hundreds.
Fails when: Each team builds its own silo with different prompts, models, and controls — cost, security risk, and maintenance complexity explode.
CH 16 · ANALYSIS

7 · Security: Defense in Depth vs. Attack Vectors

Protection lives at every layer, not one vault. Most AI attacks target content the model trusts — prompts, memory, retrieval — rather than the code.
Why it works: Because agents produce probabilistic output and act on retrieved content, protecting the reasoning process (integrity, behavioral control, accountability) matters as much as protecting infrastructure. Layering means one bypass doesn't compromise everything.
Fails when: A single control is trusted to stop every attack, or an over-permissioned agent takes damaging actions — least privilege and human approval are missing.
CH 17 & 23 · ANALYSIS

8 · Continuous Improvement & Drift (AIOps)

Deployment starts the operational lifecycle. Observe → Evaluate → Improve → Redeploy runs forever, with drift detection watching for silent performance decay.
Why it works: AI systems change even when developers do nothing — knowledge ages, patterns shift, attack techniques evolve. Observability detects drift; evaluation confirms its impact; the loop adapts before failure becomes public.
Fails when: No drift monitoring exists — a model that performed well last year silently decays until a costly incident reveals it.
