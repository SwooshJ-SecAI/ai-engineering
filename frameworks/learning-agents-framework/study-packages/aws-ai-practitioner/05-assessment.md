## Answer Key

**A1.** (a) RAG — the catalog/policies change weekly, so a knowledge-access problem; fine-tuning would go stale immediately and needs retraining. (b) Amazon Bedrock (Knowledge Bases provides managed RAG). (c) It grounds answers in retrieved source documents rather than the model's frozen, generic knowledge.

**A2.** (a) Amazon Comprehend (sentiment + PII detection). (b) SageMaker requires building/training a custom model — unnecessary effort when a pre-built service already does the task. (c) Pick the highest-abstraction service that solves the problem; only drop to custom ML when nothing pre-built fits.

**A3.** (a) Temperature — low for the compliance FAQ (deterministic), high for marketing copy (creative). (b) Temperature reshapes the next-token probability distribution: low sharpens it toward the most probable token (repeatable); high flattens it so lower-probability tokens are chosen (varied).

**A4.** (a) Model drift (degradation as real-world data shifts). (b) SageMaker Model Monitor. (c) RAG addresses missing knowledge/context, not a model whose learned patterns have gone stale — drift is fixed by retraining/updating, not by injecting documents.

**A5.** (a) SageMaker Clarify (bias detection + explainability). (b) Bedrock Guardrails (runtime content/PII filtering). (c) Clarify is an analysis/measurement tool applied to data and models; Guardrails is a runtime enforcement control on model input/output — measurement vs enforcement.

**B1.** B. **B2.** B. **B3.** B. **B4.** B. **B5.** B.
